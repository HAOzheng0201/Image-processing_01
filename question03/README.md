# 问题 3：彩色图像转换为灰度图（15 分）

本题实现 `g = rgb1gray(f, method)`，将一张 24 位 RGB 图像转换成灰度图。转换方式包括 `"average"` 和 `"NTSC"`，其中 `"NTSC"` 为默认值。对 `mandril_color.tif`、`runner.jpg` 分别使用两种方法，展示结果并比较差异。

第 2 题从二维灰度数组中提取数据；本题则从三维 RGB 数组计算出二维灰度数组。这里的“黑白图像”仍指灰度图，不要求将像素分成只有黑、白两类。

## 1. RGB 转灰度改变了什么？

RGB 图像中，每个像素由红、绿、蓝三个分量表示。每通道 8 位时，每个分量的范围为 0～255，三个通道合计为每像素 24 位。例如：

```python
[255, 0, 0]      # 纯红
[0, 255, 0]      # 纯绿
[0, 0, 255]      # 纯蓝
```

灰度图每个像素只保存一个灰度值。因此，转换过程需要用一个数概括原来三个分量的信息。图片的高和宽保持不变，数组形状从 `(H, W, 3)` 变成 `(H, W)`。

转换会丢失颜色信息。不同颜色可能得到相同灰度值，因此通常不能从灰度图唯一恢复原来的 RGB 图像。转换也不是缩小图片，更不是把三个通道中的某一个直接取出来。

## 2. 两种转换方法

### 2.1 平均法

对每个像素计算三个分量的算术平均值：

$$
g_{\mathrm{average}}=\frac{R+G+B}{3}.
$$

这种方法对三个通道一视同仁。例如，纯红、纯绿和纯蓝三个像素都会得到 `255 / 3 = 85`。它保留了一种简单的整体强度描述，却无法体现人眼对不同颜色的敏感程度差异。

### 2.2 NTSC 加权法

按照题目指定的系数计算：

$$
g_{\mathrm{NTSC}}=0.2989R+0.5870G+0.1140B.
$$

绿色分量权重最大，红色其次，蓝色最小。这种加权方式考虑了人眼对不同颜色的亮度感知差异。在本题中，按指定公式直接处理 RGB 数值即可；不额外引入伽马解码等步骤，也不把该公式当成所有色彩空间通用的物理亮度定义。

比较三个简单像素，便能看出权重的作用：

| RGB 像素 | 平均法 | NTSC 法（未取整） |
|---|---:|---:|
| 红色 `[255, 0, 0]` | 85 | 76.2195 |
| 绿色 `[0, 255, 0]` | 85 | 149.6850 |
| 蓝色 `[0, 0, 255]` | 85 | 29.0700 |

同样是一个通道取 255，绿色在 NTSC 结果中更亮，蓝色更暗。这些结果由公式直接计算得到，不是实验图片的测量结果。

题目给出的系数之和为 `0.9999`，不是严格的 1。因此，白色 `[255, 255, 255]` 的 NTSC 浮点结果为 `254.9745`。代码保留题目公式，不擅自修改系数或重新归一化；保存时取最近整数，这个像素会成为 255。

## 3. 为什么两种方法在不同区域表现不同？

将两个公式相减，可得到：

$$
g_{\mathrm{NTSC}}-g_{\mathrm{average}}
\approx -0.03443R+0.25367G-0.21933B.
$$

所以，与平均法相比，绿色分量相对突出的区域倾向于更亮，蓝色分量相对突出的区域倾向于更暗。实际像素通常同时含有三个分量，应结合三者一起判断，不能看到某个物体就假定它是纯色。

当 `R = G = B = k` 时，平均法输出 k，NTSC 输出 `0.9999k`，二者几乎相同。两种方法的主要差别通常体现在颜色较鲜明的区域。

这也说明，不能简单说“NTSC 会让整幅图更亮”或“平均法一定更清楚”。整体亮暗和局部对比的变化取决于原图的颜色分布。

## 4. 函数接口与数组实现

```python
def rgb1gray(f: np.ndarray, method: str = "NTSC") -> np.ndarray:
    ...
```

| 项目 | 约定 |
|---|---|
| 输入 `f` | 非空的 `(高, 宽, 3)` NumPy 数组，类型为 `uint8`，通道顺序为 RGB |
| `method="average"` | 三通道取平均 |
| `method="NTSC"` | 使用题目指定的加权公式 |
| 省略 `method` | 使用 NTSC，例如 `rgb1gray(f)` |
| 返回 `g` | `(高, 宽)` 的 `float64` 数组，保留灰度计算的小数部分 |

题目限定输入为 24 位 RGB，因此本函数明确检查 `uint8` 和三个通道，不自动把浮点图、RGBA 图或灰度图解释为符合要求的输入。参数字符串区分大小写。

函数也无法仅凭数组形状判断通道究竟是 RGB 还是 BGR。这里统一用 Pillow 读取，确保输入是 RGB；若以后使用 OpenCV 的常规彩色读取结果，必须先将 BGR 转成 RGB。

核心切片是：

```python
rgb = f.astype(np.float64)
red = rgb[:, :, 0]
green = rgb[:, :, 1]
blue = rgb[:, :, 2]
```

前两个 `:` 表示全部行和列，最后的索引选择通道。因此 `red`、`green`、`blue` 各是一张二维数组。对它们写加法、乘法时，NumPy 会按相同位置逐元素计算，一次完成所有像素的灰度转换，无需两层循环。

本题的核心转换由上述公式自行实现，没有调用 `Image.convert("L")`、`cv2.cvtColor(..., COLOR_RGB2GRAY)` 或 `skimage.color.rgb2gray` 代替。现成函数可能使用不同系数或输出范围，不能仅凭函数名称就认为它们严格等同于本题公式。

## 5. 为什么先转浮点，保存时再转整数？

### 5.1 避免 uint8 加法溢出

8 位无符号整数只能表示 0～255。若直接让 `uint8` 数组相加，超过范围的结果可能回绕。例如，对 `uint8` 数组计算 `200 + 100`，可能得到 44，而不是 300。

因此，应当先执行 `f.astype(np.float64)`，再计算三通道之和。先相加、最后才转浮点不能修复已经发生的溢出。

`astype` 只改变数据类型，不改变数值尺度：200 变为 200.0，不会自动变成 `200 / 255`。本程序始终在 0～255 尺度上计算。

### 5.2 保留小数结果

平均值和加权和都可能含有小数。函数返回 `float64`，避免在算法内部过早取整，也便于后续第 6 题直接使用 NTSC 灰度结果进行滤波。

保存为普通 8 位灰度 PNG 时，单独执行：

```python
gray_uint8 = np.clip(np.rint(gray), 0, 255).astype(np.uint8)
```

- `np.rint`：取最近整数；恰好位于两个整数中间时取其中的偶数，例如 2.5 取 2，3.5 取 4。
- `np.clip`：把值限制在 0～255 范围内。对本题合法输入与公式，结果本应在范围内，这里保留明确的保存边界。
- `astype(np.uint8)`：转换为 8 位整数，供 Pillow 保存为灰度图片。

直接 `astype(np.uint8)` 会截去正数的小数部分，与取最近整数不同。代码没有用保存后的整数数组覆盖浮点结果，因此图中对比和终端差异统计仍使用原始计算值。

## 6. 实验安排与结果分析

两张原图分别生成“原始 RGB—平均法—NTSC”的三联图。两幅灰度子图都使用 `cmap="gray", vmin=0, vmax=255`，防止自动拉伸各自的显示范围影响比较。

运行后可以重点观察：

- `mandril_color.tif`：山魈面部有明显的红、蓝区域，适合对照颜色与灰度变化。结合原图观察蓝色区域在 NTSC 法下是否更暗，红色区域与周围区域的对比如何变化。
- `runner.jpg`：观察草地、肤色、服装和背景。不同区域含有不同的 RGB 比例，应分别比较，不只看整张图的平均亮度。

现有的 [mandril 对比图](results/mandril_color_comparison.png) 中，面部蓝色区域在 NTSC 结果里比平均法更暗，体现了蓝色权重从 1/3 降到 0.1140 的影响。这里的结论限定于所观察区域，不能推广成整张 NTSC 图都更暗。[runner 对比图](results/runner_comparison.png) 可按同样方式逐区域阅读。

用一个混合颜色像素帮助理解：`[60,90,180]` 的平均法结果为 110，NTSC 结果为 `17.934+52.83+20.52=91.284`，两者相差 18.716。这个自拟像素并非从图片取样；它说明蓝色分量较突出时，为什么加权灰度可能更低。若换成 `[60,180,90]`，平均值仍为 110，NTSC 则为 133.854。三个分量总和相同，颜色比例不同，加权结果就不同。

程序还打印两种浮点结果的平均绝对差和最大绝对差：

$$
\operatorname{MAE}=\frac{1}{HW}\sum_{r=0}^{H-1}\sum_{c=0}^{W-1}
\left|g_{\mathrm{average}}(r,c)-g_{\mathrm{NTSC}}(r,c)\right|.
$$

平均绝对差表示每个像素平均相差多少灰度级；最大绝对差表示差异最大的像素相差多少。这里没有标准答案图像，因此这些数值只描述两种方法的差异，不能用来证明其中一种质量更好。

## 8. 可以用来检查理解的几个问题

1. 为什么纯红和纯绿在平均法中得到相同灰度，在 NTSC 法中却不同？
2. 为什么从 `(H, W, 3)` 变成 `(H, W)` 后，图片的空间尺寸没有变化？
3. 为什么不能先用 `uint8` 数组求和，再把结果转成浮点？
4. 为什么显示和保存使用的数据类型可以不同？
5. 两种方法差异很大，是否就能说明有一种实现错误？

回答这些问题时，可以分别回到权重公式、通道切片、数值范围和实验比较的定义。理解这些环节，比记住一条灰度转换语句更有用。
